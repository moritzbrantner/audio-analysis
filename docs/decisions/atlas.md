- **How to use this Decision Atlas**
  - This is the canonical, append-only record of **what reusable Audio Analysis should prioritize and provide**. It does not replace [the existing architectural ADRs](../adr), [ownership records](../ownership/audio-package-ownership.json), implementation code/tests, or GitHub issues.
  - There are exactly **two semantic leaf kinds**: **Decision**, an owner-selected direction, and **Question**, an unresolved consequential choice marked `[question]`. Navigation branches are not entries of another kind. Questions are not automatically work blockers.
  - Explicit dotted IDs are stable: append new sibling IDs, never renumber, delete, reorder, or reuse an ID. When answering a Question, preserve it and append a Decision citing `Answers X.Y`; when changing direction, append a Decision citing `Supersedes X.Y`.
  - Consult applicable Decisions before feature prioritization. When an unresolved Question materially determines a task, ask **one owner question at a time** instead of silently choosing. Issues hold implementation tasks and acceptance contracts; code and tests, not this Atlas, prove completion.
  - Keep technical implementation choices in the existing ADRs or a future technical-decision record **only when needed**; do not duplicate architectural authority here. Follow the [reuse-first capability policy](https://github.com/moritzbrantner/coding-agent-conventions/blob/main/docs/adr/0001-capability-internalization.md): external providers are valid; first-party replacement requires comparative evidence and an actual consumer.

- **1** Capability direction
  - **1.1** Near-term priority
    - **1.1.1** **B — Speech analysis first (owner-selected 2026-10-16).** Prioritize reusable transcription/ASR, speaker diarization, voice activity detection, alignment, and recording/capture-quality measurement in the coming months, guided by real consumer evidence from [Vox](https://github.com/moritzbrantner/vox) and [Native WhisperX](https://github.com/moritzbrantner/native-whisperx). Keep music/DJ analysis, generation and other established audio capabilities supported, but rank **new discretionary milestones** behind the speech focus. Do not defer necessary correctness/security/consumer fixes, change consumers' application/consent/workflow authority, declare unverified functionality complete, or replace external implementations without the existing evidence gates. Scope tracking: [#150](https://github.com/moritzbrantner/audio-analysis/issues/150); continuing music commitments: [#69](https://github.com/moritzbrantner/audio-analysis/issues/69) and [#130](https://github.com/moritzbrantner/audio-analysis/issues/130).
  - **1.2** First speech milestone
    - **1.2.1** [question] Which **one** consumer-visible speech capability should lead the speech-first roadmap? **A:** capture-quality and VAD behavior in a real Vox recording/review workflow; **B:** transcription and alignment correctness/latency in a Native WhisperX real-file workflow; **C:** speaker diarization/overlap handling in a Native WhisperX real multi-speaker workflow. Check the existing implementation and close gaps rather than rebuild delivered foundations. The chosen slice needs independent reference evidence, runtime measurements where relevant, and real consumer/Pages-equivalent acceptance. Tracked by [#150](https://github.com/moritzbrantner/audio-analysis/issues/150).
    - **1.2.2** **A — Capture quality and VAD first (owner-selected 2026-10-16).** **Answers 1.2.1.** Make recording/capture quality and genuine voice activity detection the first speech capability milestone, validated end-to-end through Vox's existing recording → review workflow. Preserve and reuse [audio-analysis #137](https://github.com/moritzbrantner/audio-analysis/issues/137) capture metrics and the existing transcription VAD providers; RMS sound activity is not equivalent to identified speech. Keep unverified/unsupported activity states explicit, consumer-specific scoring/consent and session UX in Vox, and real-device acceptance in [Vox #91](https://github.com/moritzbrantner/vox/issues/91). [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151) owns the focused speech/VAD capability slice and real consumer acceptance; [#150](https://github.com/moritzbrantner/audio-analysis/issues/150) tracks the speech-first roadmap. Do not automatically start transcription/alignment or speaker-diarization expansion, duplicate existing kernels, create new shells, or replace external providers without comparative evidence. The initial delivery mode is still an open choice at **1.3.1**.
  - **1.3** Capture-quality and VAD delivery horizon
    - **1.3.1** [question] For the selected first speech milestone, **which input mode must pass real Vox acceptance first?** **A:** finite post-recording speech/non-speech segments and quality evidence in session review; **B:** bounded live/incremental capture-quality and VAD observations during microphone recording (with clear unknown/degraded states); **C:** both live and post-recording with an explicit same-input parity contract. All options preserve [Vox #91](https://github.com/moritzbrantner/vox/issues/91)'s already-selected Android phone and PC built-in microphone test routes; Vox retains presentation/consent policy. Choosing the horizon scopes [#151](https://github.com/moritzbrantner/audio-analysis/issues/151), not a wholesale new streaming framework.
    - **1.3.2** **C — Live and post-recording capture quality/VAD with same-input parity (owner-selected 2026-10-16).** **Answers 1.3.1.** The first speech milestone must exercise **both** bounded incremental observation during a real Vox recording **and** finite post-recording observation over that recording, not defer either mode to a later roadmap phase. For the same validated PCM, timebase, model/provider, version, configuration and supported input, the completed live/finalized observations must agree with the finite reference within declared numerical and time-boundary tolerances. Preserve segment coverage, capture interruptions, resampling offsets, uncertainty and provenance; document the allowed lookahead/finalization behavior instead of assuming chunk-size-independent instantaneous predictions. Prove correctness against independent reference/annotated fixtures, bounded incremental work and representative runtime cost, and the actual Vox recording → review workflow under [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151), coordinated with [Vox #38](https://github.com/moritzbrantner/vox/issues/38) and [Vox #40](https://github.com/moritzbrantner/vox/issues/40). Runtime-specific missing VAD support must be explicit, never reported as no speech or parity. This does not select a new provider/transport, require identical output from different models, override Vox's privacy/UX/fluency-scoring policy, imply public hosted inference, or mark [Vox #91](https://github.com/moritzbrantner/vox/issues/91)'s real-device capture checks complete.
  - **1.4** Live Vox experience
    - **1.4.1** [question] Given that both live and post-recording analysis are required, **what should the optional, nonjudgmental live recording view expose to the speaker?** **A:** compact input-health and detected-speech status while recording, with detailed segments available after stopping; **B:** an optional evolving speech/silence timeline with provisional confidence and health markers, alongside detailed post-session review; **C:** record/stop and capture-failure warnings only, with live computation running invisibly and all speech activity presented after recording. All choices keep Vox [#40](https://github.com/moritzbrantner/vox/issues/40)'s opt-in, nonintrusive live-feedback policy; no stutter/severity score, intervention instruction or audio upload is implied. Reconcile the selected UX with [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151).
    - **1.4.2** **B — Optional evolving live speech/silence timeline (owner-selected 2026-10-16).** **Answers 1.4.1.** Vox's recording view should optionally show a continuously updated speech/non-speech timeline with **explicitly provisional boundaries/confidence when the selected VAD provider actually supplies them**, plus separate microphone/capture-health indicators and explicit unmeasured/stale/unsupported states. A finalized, more detailed timeline is available in the after-recording review. This is user-controlled, unobtrusive information only: no automatic stutter/severity scoring, distracting alerts, coaching, changed audio handling or uploaded recordings. The timeline uses the existing recording descriptor/session clock and retains input-versus-intervention provenance; use the same underlying reusable, provider-identified [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151) VAD/capture observations and [1.3.2](https://github.com/moritzbrantner/audio-analysis/blob/main/docs/decisions/atlas.md)'s live-to-finite parity contract, not a second browser signal classifier. Vox [#40](https://github.com/moritzbrantner/vox/issues/40) owns interaction, [#38](https://github.com/moritzbrantner/vox/issues/38) owns incremental freshness/work constraints and [#91](https://github.com/moritzbrantner/vox/issues/91) retains real-device acceptance. This is intent, not implementation evidence.
    - **1.4.3** [question] **How should provisional speech boundaries evolve on the optional live timeline before finite post-recording confirmation?** **A:** display a recent, clearly provisional window whose boundaries can be revised until finalized, then keep older stable segments; **B:** show only already-finalized VAD segments live (with the provider's necessary lookahead delay) while still showing separate current input-health status; **C:** show an immediate provisional timeline without in-session boundary corrections, then replace/reconcile it with the finite timeline after stopping. All choices preserve the 1.3.2 same-input *finalized* parity gate, explicit stale/unsupported states and user-controlled nonjudgmental presentation under Vox #40; they must not invent a numerical confidence for providers that lack one. Reconcile this decision in [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151) and [Vox #40](https://github.com/moritzbrantner/vox/issues/40).
    - **1.4.4** **A — Revise a recent bounded provisional window, then finalize older speech intervals (owner-selected 2026-10-16).** **Answers 1.4.3.** Vox's optional, nonjudgmental live speech/silence timeline must show recent VAD observations as explicitly *provisional*, permit speech/non-speech boundaries in that bounded window to move, appear or disappear as more audio arrives, then make older segments *final* only when the selected provider's declared lookahead/finalization contract allows it. A final segment must not silently change within the same analysis revision. Provisional and finalized segments must retain session-relative timestamps, provider/configuration provenance and explicit confidence only where supported. Handle gaps, resampling, cancellation, stale results and overload as unknown/degraded rather than turning missing evidence into silence or attributing speech to a specific person. After recording stops, reconcile all finalized live segments against the same-input finite analysis within the [1.3.2](https://github.com/moritzbrantner/audio-analysis/blob/main/docs/decisions/atlas.md) parity tolerances, and surface an explicit revised analysis version if later correction is needed. Reuse the Audio Analysis [#151](https://github.com/moritzbrantner/audio-analysis/issues/151) generic VAD observations and the existing Vox [#38](https://github.com/moritzbrantner/vox/issues/38) incremental semantics, [#40](https://github.com/moritzbrantner/vox/issues/40) UI and [#25](https://github.com/moritzbrantner/vox/issues/25) provenance boundary. The choice does **not** prescribe a specific lookahead time, VAD model, backend, transport, confidence algorithm or recording policy; those follow technical evidence. This is a required product/acceptance contract, not an implementation claim.
    - **1.4.5** [question] **When the live timeline detects human speech but the speaker's identity is not established, what should the user see?** **A:** show detected *speech activity* without speaker attribution, alongside an independent unknown/single-speaker-quality indicator; do not infer that the speech is the user's. **B:** withhold the speech/silence timeline while speaker attribution is unknown, displaying only capture health and an explicit explanation. **C:** add separately labeled self/other/unknown segments only where an independently supported speaker-identification provider can justify them, and otherwise show unknown/unattributed activity. This is a product presentation choice, not permission to rewrite a VAD into a diarization or identity model; [Vox #40](https://github.com/moritzbrantner/vox/issues/40) owns the interface and [Vox #25](https://github.com/moritzbrantner/vox/issues/25) owns consumer interpretation. [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151) remains generic speech activity plus same-input parity; [Vox #91](https://github.com/moritzbrantner/vox/issues/91) retains background-speech acceptance. Preserve the existing prohibition on presenting unidentified background speech as the user's fluent speech.
    - **1.4.6** **A — Show unattributed speech activity when speaker identity is unknown (owner-selected 2026-10-16).** **Answers 1.4.5.** Vox's optional live timeline and detailed after-recording review show generic, provider-backed speech/non-speech observations even when the speaker is not identified; label the speech as **unattributed**, not as the user's speech, and display the independent known/unknown/mixed-speaker quality state separately. Speech detection by VAD is not speaker recognition, identity verification, stuttering detection or permission to assign fluency outcomes to the current user. Preserve the current capture-quality gate: unknown or overlapping speakers are not silently scored as clean user speech, and genuinely unavailable VAD remains explicitly unmeasured/unsupported, not silence. Reuse the same [Audio Analysis #151](https://github.com/moritzbrantner/audio-analysis/issues/151) speech-activity evidence for both bounded live and finite paths; [1.3.2](https://github.com/moritzbrantner/audio-analysis/blob/main/docs/decisions/atlas.md) still requires same-input finalized parity and [1.4.4](https://github.com/moritzbrantner/audio-analysis/blob/main/docs/decisions/atlas.md) still governs provisional revisions. Vox [#40](https://github.com/moritzbrantner/vox/issues/40) owns labels and opt-in UI, [#25](https://github.com/moritzbrantner/vox/issues/25) owns provenance/interpretation, and [#91](https://github.com/moritzbrantner/vox/issues/91) retains background-speech physical acceptance. Do not add a new speaker model, implied user identity, hidden remote processing, or a second VAD implementation. This decision is product intent, not verified implementation.
    - **1.4.7** [question] **Should the first post-recording Vox review let the user identify which unattributed speech intervals were theirs?** **A:** allow optional per-interval *manual self/other/unknown* tagging with original VAD evidence retained separately, no automatic validation or scoring inferred from a self-report; **B:** keep only Vox's existing whole-session single-speaker declaration and unattributed timeline, without new interval tagging in the first milestone; **C:** show all unknown-attribution intervals without any manual identity editing until an independently validated speaker-identification capability is available. This is a Vox product/annotation decision, not a change to generic Audio Analysis VAD, and must respect [Vox #23](https://github.com/moritzbrantner/vox/issues/23)'s separate annotation authority, [Vox #25](https://github.com/moritzbrantner/vox/issues/25)'s evidence provenance and [Vox #40](https://github.com/moritzbrantner/vox/issues/40)'s nonjudgmental review. Regardless of choice, do not score unverified background speech as the user's speech.
